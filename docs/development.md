# 开发指南

## 开发环境

### 必要工具
- **Keil μVision 5**：主要构建工具链
- **VS Code + EIDE 扩展**：开发环境
- **调试器**：ST-LINK 或 J-Link
- **Git**：版本控制

### 工程配置
- 具体编译目标、优化等级、调试器配置，以实例工程中的 `.uvprojx` 或 `.eide/eide.yml` 为准

## 开发流程

### 1. 规划阶段
- 在 `NEXT_MISSION.md` 中定义需求
- 识别受影响模块
- 评估资源影响（ROM/RAM）

### 2. 实现阶段
- 遵循 `dev-guidelines/rules/` 中的编码规则
- 模块化实现，保持单一职责
- 频繁提交，使用描述性提交信息

### 3. 测试阶段
- 构建零警告
- 尽可能对工具进行单元测试
- 必须进行硬件验证
- 性能分析与调优

### 4. 文档阶段
- 更新模块文档
- 添加 API 注释（Doxygen 格式）
- 必要时更新架构图

### 5. 发布阶段
- 代码审查
- 合并到主分支
- 创建版本标签
- 更新变更日志

## 编码规范

### 语言规则
- C99 标准
- 包含 `<stddef.h>` 获取 NULL
- 根据硬件是否具备 FPU 决定是否使用浮点运算

### 命名约定
- 函数：`ModuleName_FunctionName`
- 变量：`camelCase`
- 宏：`UPPER_CASE`
- 类型：`type_name_t`

### 代码组织
- 每个函数单一职责
- 头文件定义 API 接口
- 静态函数用于内部实现
- 统一缩进（4 空格）

## 调试流程

### 硬件调试
1. 连接调试器到目标板
2. 在关键路径设置断点
3. 使用 DWT 等硬件计时监控执行时间
4. 检查外设寄存器
5. 用示波器验证时序

### 常见问题
- **栈溢出**：检查 map 文件中的栈使用
- **时序违规**：使用 DWT 计数器进行性能分析
- **内存损坏**：使用内存监视点
- **中断冲突**：检查优先级设置

## 性能优化

### 分析方法
- 使用 DWT 周期计数器测量关键路径
- 监控各任务执行时间
- 分析汇编输出发现瓶颈

### 优化策略
- 优先查表而非计算
- 使用 DMA 进行数据搬运
- 最小化中断延迟
- 优化数据结构

## 版本控制

### 分支策略
```
main（稳定版本）
└── develop（集成分支）
    ├── feature/*（新功能）
    ├── bugfix/*（错误修复）
    └── release/*（发布准备）
```

### 提交准则
- 使用约定式提交：`type(scope): description`
- 类型：`feat`、`fix`、`docs`、`style`、`refactor`、`test`
- 保持提交聚焦且原子化

## 质量保证

### 代码审查
- 检查编码规范遵守情况
- 验证资源使用
- 确认错误处理
- 确保文档更新

### 测试要求
- 构建验证（零警告）
- 硬件功能测试
- 性能基准测试
- 回归测试

## 故障排除

### 构建问题
- 清理并重新构建
- 检查包含路径
- 验证工具链安装
- 更新项目依赖

### 运行时问题
- 检查电源稳定性
- 验证硬件连接
- 监控噪声/干扰
- 使用逻辑分析仪分析时序

### 工具集成
- VS Code 设置在 `.vscode/` 中
- EIDE 配置文件位于实例目录 `.eide/` 下
